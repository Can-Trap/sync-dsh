# Framework — the source↔OD mapping model (both ways), teardown, accelerator

The mental model behind every phase: a codebase and an Open Design workspace are **two views of one design
system**, linked by a manifest of pairs. Forward (source → OD) publishes; backward (OD → source) pulls
designer edits into managed blocks. Drift on either side re-anchors the pair.

## Two modes, produces one or both (they are SEPARATED options)
- **Mode B — a design system** (`DESIGN.md` + light+dark `tokens.json`, Phases 01–03). Reusable across
  projects; the token + capability contract (links/nav/effects/light+dark).
- **Mode A — a project** — a locally built `od-bundle/` (OD-safe rendered pages + sentinel + anchor)
  uploaded into the OD project via the agent-bridged plan (Phases 01, 04–05, 07–09). A concrete, viewable
  artifact.
Each mode stands alone — ask for one and only its phases run. **Default when the user didn't say is
BOTH** (DS first, then project); `assets/graphs/decision-tree.dot` shows when to build only one.

## The mapping model (source ↔ OD)
```
codebase                         .design-sync/manifest.json                Open Design
  globals.css  ── extract ──►      pairs: [{src, od,                 ──►   design-systems/<id>/tokens.json
  components/  ── build+upload ►      srcHash, odHash}]              ──►   OD project (via upload plan)
  src file     ◄── pull (block) ──  (drift = a moved hash)           ◄──   OD designer edit
```
- **Forward** (detect → extract → DS → build `od-bundle/` → validate → grade → upload): the codebase
  drives OD.
- **Backward** (pull, review-gated → managed block): OD edits flow into a `design-sync:start:<name>` block
  in source; human content around it is never touched.
- **Drift** (`ods-manifest.js drift`): a changed hash names which side moved and which path to take —
  src → driver re-run, od → 06-pull (`references/09-upload-sync.md`). Coalesce all drift, run each
  affected phase once.

## Capability guarantee (must hold in every produced DS/project)
**Links · Navigation · Effects · Light+Dark theme** — verified, not assumed. They are established across
extract (02, both themes), DESIGN.md (03, all four sections), the build's render runtime (05, theme + menu
toggle), and asserted per page at the validate gate (07, same predicates as `ods-verify.js`). If any is
missing, the run is not DONE.

## Teardown (everything is reversible)
- Delete `od-bundle/` + `.ds-sync/` (build output + staged scripts — both gitignored, both regenerated by
  the next build) to reset the local pipeline without touching OD or source.
- `.design-sync/` is mostly gitignored working state — delete the machine-local files to reset the run; the
  committed durable set (`config.json`, `NOTES.md`, `conventions.md`) and the REAL artifacts at their OD
  paths persist.
- Remove a published project via OD MCP `delete_project` (explicit `confirm:true`) or delete its
  `resolvedDir`. Remove a DS by deleting `design-systems/<id>/` (reload OD after).
- Pulled managed blocks: delete the `design-sync:start:<name>…end` region from the source file; the human
  content outside it is intact, so removal is clean.

## Optional Workflow accelerator
The mechanical middle of the pipeline is already one command: `ods-resync.js` (the driver) chains
`ods-build.js` → `ods-diff.js` → `ods-validate.js` → `ods-capture.js` and prints one verdict. For a
repeatable end-to-end run, wrap the phase scripts — `ods-detect.js` / `ods-extract-tokens.js` /
`ods-build-design-system.js` / the driver (or `ods-build.js`/`ods-validate.js`/`ods-diff.js`/
`ods-capture.js` individually) / `ods-upload-plan.js` / `ods-upload-verify.js` — in a Workflow/task-runner
that shells them in order and stops on the first non-zero exit. The scripts are composable (stdin-free,
arg-driven, deterministic exit codes: 2 = usage/review, 1 = failure, 0 = ok — `ods-pull.js` review = 2,
`ods-manifest.js drift` = 1). This is an accelerator, not a requirement — the autonomy loop
(`references/self-management.md`) does the same work interactively, and the upload itself always needs the
agent (MCP bridge).
